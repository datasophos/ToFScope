# vtk-only 3D workspace implementation plan

**Goal:** Replace every production 3D Plotly path with vtk while preserving current visualization controls and saved views.

**Architecture:** Render complete regularized volumes with vtk and represent thin, sparse, incomplete, negative or threshold-limited data using vtk point geometry without inventing missing samples. Render tiles as independent vtk scenes with the existing page and camera state; overlay supports all visible signals. Display-only interpolation never changes analysis data.

**Constraints:** Preserve acquisition files, original-resolution analysis, shared scales, linked/independent cameras, page state, per-signal styles, and visible warnings about interpolation and sampling. Renderer failures must be explicit and retryable.

- [x] Add tests and vtk geometry for incomplete, thin, constant, negative, and threshold-limited signals, including exact coordinates and intensity values.
- [x] Support visible signal counts in overlays with bounded GPU work and independently styled layers.
- [x] Implement tiled vtk scenes with paging, shared scales, and linked or independent camera persistence.
- [x] Remove the 3D Plotly renderer and replace fallback messages with explicit vtk errors or limitations.
- [x] Update browser tests, documentation, and run unit, type, browser, and relevant Python verification; regenerate frontend assets.
